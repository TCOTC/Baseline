# 基线 / Baseline

> 和之前的你对比。

为每个目标定义**「什么算推进它」**，把活动归属到目标，累加成一条可以对比过去的曲线。

---

## 它解决什么问题

不是「不知道该做什么」。是**做了也不算数**——没有对比就没有位移，没有位移就没有进展。

所以它不做的事，和它做的事一样重要：

| 不做 | 为什么 |
|---|---|
| 不用红绿表示好坏 | 红色携带「错误 / 衰退」语义，会把它变成评判工具 |
| 不做进度条 / 百分比 | 方向性目标没有终点，百分比会暗示「快完成了」，那是假的 |
| 不做连胜 / 连击 | 把「中断」定义成失败，而中断是必然的 |
| 不画平滑曲线 | 数据是离散累积的，平滑会伪造出一个从未发生过的渐进过程 |
| 不替你判断该做什么 | 它只显示哪条线在动、哪条没动 |

## 快速开始

```powershell
cd web
pnpm install
pnpm build          # 产物落进 internal/webui/dist

cd ..
go build -o bin/baseline.exe ./cmd/baseline
.\bin\baseline.exe init          # 建库（幂等）。会把库的完整路径打出来
.\bin\baseline.exe serve         # 打开 http://127.0.0.1:7717
```

**前端是编进二进制的**：改完 Vue 必须重新 `pnpm build` + `go build`，否则页面还是旧的。
这是这套结构里唯一一个「改了没生效」的坑。

想先看长什么样——演示数据写在 `data/_demo.db`，不碰正式库：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/demo.ps1
.\bin\baseline.exe --db data\_demo.db serve --debug
```

### 开发：浏览器就是主界面

```powershell
# 终端 1：Vite，改 Vue/CSS 即时生效
cd web; pnpm dev

# 终端 2：Go，把页面反向代理到 Vite
.\bin\baseline.exe --db data\_demo.db serve --dev --debug
# 打开 http://127.0.0.1:7717
```

一个地址同时给浏览器、Playwright 和 Electron 用。**没有第二套界面**。

### 桌面窗口

```powershell
cd web
pnpm electron                 # 生产模式：加载编进 exe 的界面
$env:BASELINE_DEV='1'; pnpm electron   # 开发模式：加载 Vite（需要 pnpm dev 在跑）
```

关掉窗口**不等于退出**，只是收进托盘——托盘是「随手记一条」的入口，
关一次就退出的话它就没意义了。真要退出走托盘右键菜单。

窗口是**无边框 + 自绘顶栏**：

- 顶栏横跨整个窗口宽度，它是窗口的边框，不是页面的头部，所以里面不放产品名、不放日期。
- 按钮尺寸（46×40）、图标（Segoe Fluent Icons 的 `E921`/`E922`/`E923`/`E8BB`）都来自
  在真实 Windows 11 标题栏上取样，和系统按钮摆一起看不出不是一家的。
- 拖动走 Chromium 的 `-webkit-app-region: drag`，双击最大化、Aero Snap 都跟着系统走。
- 图标边缘那招 `transform: translateZ(0)` 仍然要留着：Windows 上的 Chromium 一样会给
  文字上 LCD 次像素，透明背景的合成层才真的关掉。

**左右两栏各自独立滚动。** 一列是「三条曲线的现状」，一列是「这些天做过什么」，
长度差得很远；绑在同一个滚动条上时，看时间线就一定会把卡片推出视野。
右侧那条滚动条要**贴住窗口右边缘**，所以右内边距加在滚动容器自己身上（`.log`），
不能加在父级 `.right` 上——加在父级会把 `.log` 整体推左一百多像素，滚动条跟着进来。

### 打包

```powershell
cd web
pnpm run dist    # → dist-electron/Baseline Setup 0.1.0.exe（NSIS，约 120 MB）
```

Electron 的体积是明码标价的：安装包一百多 MB、常驻内存一百多 MB。
换来的是**不用在早期处理 WebView 差异**、DevTools 原生可用、Playwright 能直接驱动。

### 记一条

时间是**下新上旧**的一条流水，最新的贴着底部输入框。写一句，回车——记的是「刚做了什么」。

- **不选日期**。记录只能发生在现在。补记的语义由内核定：过去的日子冻结，
  **补一条旧账不会把曲线往回改，只会在今天抬一格**——意思是「你今天才记下来」，
  而不是「你三天前做过」。
- **写一句而不是点一下**。备注是这条流水上唯一有信息量的东西。
- 提交后**整屏重取**：Go 重算今天的快照，流水回到最新，输入框清空并重新聚焦。
  不做局部插入——卡片上的数字和曲线末端一旦各算各的，迟早会显示成两个数。
- 有两个以上能手工打卡的目标时才出目标选择器；只有一个就把名字写进 placeholder。
- **选了目标之后，如果那个目标下有两条以上手工规则，才会再问一句「这条记录算哪条规则」。**
  只有一条就不问——那一条唯一能收它，内核自己会归。两条以上必须问，因为
  「它算哪一条」只有你知道，工具替你挑一条出来就是一条假曲线。
  没选就按「记下」，它不会提交，而是把选择器点亮：**该动手的地方自己说话**。

### 新建目标

左栏左下角有个加号。**没有数量上限**——建目标必须一并写下判定规则，写不出就不让建；
而每张卡片底部永远印着那条规则本身。

点开是**五步固定骨架**，不是自由聊天：

```
① 你想推进什么？        → 目标名
② 为什么是现在？        → why（为了推出③，不是问感受）
③ 什么算推进它？        → rationale，也就是卡片底部那句
④ 什么不算？            → 边界。最容易跳过、也最值钱的一问
⑤ 落到四种来源里的哪一种 → 当场算出当前值 → 建成
```

拒绝也是机械的，不靠 AI 发挥：③ 空着不放行；来源需要对象时（git 仓库、外部数据）
空着也不放行（「空着就等于什么都算」）；④ 跳过了会记账但在确认页明说
「没划边界，以后这条曲线会说谎」。

**AI 在这里没有位置。** 对话要问什么是产品定死的，判据也全是机械的。

### 目标详情

**点任意一张卡片**进入这个目标的详情页，整个窗口只显示它：

- 名字、当前值、为什么想做，以及一条**大两倍多的曲线**（卡片上 44px，这里 116px）。
- **判定规则**：列出这个目标的全部来源，可以删，也可以补一条。
- **修改 / 归档 / 删除**。
- 这个目标自己的记录。

详情页走的是**查询串路由**（`?goal=N`），刷新、直接粘链接进来都还在这一屏。

**删除和归档不是一回事，界线画在「有没有记录」上：**

| | 条件 | 结果 |
|---|---|---|
| **删除** | **一条记录都没有** | 目标和规则一起没了。留给「建错了」。 |
| **归档** | 任何状态，**必须写一句原因** | 从列表消失，曲线和记录全留着，理由接在 why 后面 |

有记录时删除按钮置灰，并把理由写在旁边（「已经记了 23 条，所以删不掉……」）——
**别让人点完了才知道**。这条判定在数据层也有一份，界面置灰只是提前说明。

### 托盘

托盘图标左键 → 打开窗口**并把光标直接放进输入框**。悬停提示就是产品名。
右键出菜单：打开 / 退出。

| `goal archive <名> --reason <原因>` | 归档。**必须写原因** |
| `source add <目标> --kind <类型> [--target] [--rationale]` | 加一条判定规则 |
| `source list <目标>` | 列出判定规则 |
| `checkin <目标> [--note] [--value] [--date] [--time] [--source]` | 记一条推进 |
| `tick` | 补齐每日快照（幂等，已写入的日期不改写） |
| `status` | 终端速览各目标当前值 |
| `ai show` / `ai set` / `ai test` | 看 / 配 / 试 AI 判定 |
| `serve [--port] [--dev] [--debug] [--token]` | 起本地服务（网页 + API） |

`serve --dev` 把前端代理到 Vite；`--debug` 多一个 `GET /__state`。

### 计分来源类型（四种，是上限）

| kind | 含义 | 状态 |
|---|---|---|
| `manual_checkin` | 手工打卡 | ✅ 已实现 |
| `git_commits` | 某个仓库的提交（可加「仅无 AI」） | ⏳ 规则可登记，未接线 |

| `derived` | 由上面几个按公式组合 | ⏳ 同上 |

## 三条设计纪律

### 1. 判定规则是产品的心脏

一个目标 = 一组计分来源。**没有计分来源的目标会被拒绝打卡**，因为它给不出「什么算推进它」。

示例——同一个 App 在两个目标下的归属完全不同：

| 目标 | 计分来源 | 效果 |
|---|---|---|
| 英语 | `Learn-English 的复习记录` | 在上面写 32 个提交，**英语曲线一动不动** |
| 不用 AI 也能做 | `标为无 AI 的仓库的提交` | 只有禁用 AI 的产出才计数 |

#### 规则决定数字，靠的是「归属」

一条记录要算数，必须归到这个目标下的**某一条**规则上。

- 归属挂在 `checkin_goals.source_id` 上，也就是挂在「记录 × 目标」这个关系上，
  不在记录上。**一次做的事可以同时推进两个目标**。
- **归属能唯一确定就自动归属**，有两条以上就由人指认。工具不替你猜。
- 归不到任何规则的记录**仍然记得下**，只是不进曲线（流水上标「·不计入」）。
- 删掉一条规则之后，原本归在它名下的记录会悬空。还在剩下唯一一条能收它的时候自动接手，
  剩两条以上就停在那里等指认——**数字会跟着掉，但界面上说得出为什么**。

判定口径只有一份实现：`internal/metrics.SourceValue`。

#### AI 判定：只判断「你做的那件事落在哪句话里」

设置页配一个 OpenAI 兼容的接口（默认 DeepSeek）就能开。它回答两个问题：

- **这条记录算哪条规则？** —— 一个目标下有两条以上手工规则时，原本只能问你。
- **这条记录该归哪个目标？** —— 记一条的时候一个目标都不选，它去全部目标的规则里挑一条。

它的权力被四条规矩框死：

| 规矩 | 为什么 |
|---|---|
| **记录先落库，它只负责事后补判** | 一条已经发生的事不该因为别人的服务器慢而记不下来 |
| 只能从你写的候选里挑，或者回答「都不像」 | 返回候选之外的 id **一律作废**（`ai.ParseReply` 核对） |
| **只填空着的格子** | 人挑过的目标、唯一能确定的那条规则，它碰都碰不到 |
| 置信度低于门槛（默认 80）就什么都不选 | **宁可留个待办，也不要一条假曲线** |

密钥加密后存在库里，口令编译在二进制里。**这不是安全边界，是提高门槛**——
能读库的人通常也能读 exe；它挡住的是按模式扫文件的窃取。明文只在内存里存在一趟，
页面拿到的永远是掩码。

### 2. 快照写入后不再改写

曲线读的是 `snapshots` 表，不是实时回扫打卡记录。快照一旦落盘就冻结
（`INSERT OR IGNORE`）——以后改了判定规则，只影响**未来**的取值，已经落盘的那段曲线保持原样。

漏跑 `tick` 会留下空缺的日子，渲染时**沿用前一个已知值**——这对累积量是正确语义
（没记录 ≠ 归零），也正好就是阶梯线的形状。

#### 今天是个例外

**过去的日子冻结，今天每次重算。** 今天还没过完，用 `INSERT OR IGNORE` 把它钉死的话，
当天第一次渲染就把今天的值定下来了：之后每记一条，卡片上的数字会涨，
曲线却停在第一次渲染的位置——**数字和线的末端当场对不上**。

这条规则顺带定义了补记：**补一条三天前的打卡，不会把曲线往回改，只会在今天抬一格。**

**数字和曲线必须同源。** `current` 和 `deltaWeek` 都取自快照序列，前端一行算术都不写。

### 3. 零硬编码颜色

所有颜色走 CSS 变量。目标色通过给容器加一个类（`.blue` / `.green` / …）注入，
组件内部只写 `var(--goal-color)`。新增一个目标只需分配一个色板，卡片、圆点、标签、曲线自动一致。

另外两条从踩坑里得到的约定：

- **SVG 内部类名必须加前缀**（`cv-line` / `cv-base` / `cv-dot`）。曾因 `.dot` 与时间线的
  `.dot` 撞车，CSS 把曲线末端的圆点拽出了坐标系。
- **数字必须 `font-variant-numeric: tabular-nums`**。
- **HTML 由 Vue 拼，样式分两层**：跨屏的令牌与原语在 `web/src/styles/`，
  组件自己的样式写在各自的 `<style scoped lang="scss">` 里；只有流水行是命令式 DOM
  （虚拟滚动要知道滚到哪儿了），它的样式必须留在全局层。

## 技术选型说明

| 层 | 选择 | 为什么 |
|---|---|---|
| 内核 | Go，单模块 | 更熟悉；编译快；纯 Go 可交叉编译 |
| 存储 | `modernc.org/sqlite`（纯 Go） | 不需要 cgo，也不依赖系统 sqlite3.dll；单机数据量小，性能不是瓶颈 |
| 界面 | Vue 3 + Vite + SCSS | HMR；组件化；样式就近，令牌仍在全局层 |
| 外壳 | Electron | 先不处理 WebView 差异；DevTools 和 Playwright 直接可用 |
| 通信 | 127.0.0.1 HTTP | 浏览器、Electron、AI 验证共用同一个地址 |

**为什么不是「内核 + Tauri」了**：判定、归属、快照这些语义已经稳定，
剩下的迭代几乎全在界面上；而界面迭代最贵的是「改一行、重启窗口、截图量像素」。
换成 Vite 之后那一步变成几十毫秒。**这次迁移买的是开发循环，不是运行时。**

**为什么 SQLite 用纯 Go 驱动**：`rusqlite` 那一版是 bundled C，需要 cgo/现场编译。
纯 Go 驱动冷编译稍慢、产物大几 MB，但增量构建和交叉编译都简单；
单用户几千行数据，性能差异感觉不到。
（实测：modernc 冷编译 7 秒、增量 0.3 秒、9.5 MB；ncruces 的 WASM 方案冷编译 15 秒、
13.4 MB，所以选了前者。）

**为什么界面是 Vue 而不是服务端拼 HTML**：旧版用字符串拼整页，好处是「一个渲染器」；
代价是任何交互都要整页重载，而且验证只能靠截图。现在 Vue 只负责画，
**数字、曲线路径、甚至「+3 / 持平」都仍由 Go 算好**——渲染器换了，判定口径没换。

**为什么不保留旧版的调试桥**：它能在页面里执行任意 JS，而那正是 Playwright 的
`page.evaluate` 天生就会的事。少一个常开的入口，就少一条攻击面。

## 调试基础设施

```powershell
# 全量：构建 + 演示数据 + 起服务 + 浏览器 28 项 + Electron 9 项
powershell -ExecutionPolicy Bypass -File scripts/check.ps1

# 只跑浏览器（服务要已在跑）
node web/scripts/check-ui.mjs

# 只看数字，不开浏览器
Invoke-RestMethod http://127.0.0.1:7717/__state | ConvertTo-Json -Depth 4
```

`check-ui.mjs` 覆盖：三张卡片、当前值、30 格条纹、阶梯路径、虚拟滚动只画可见行、
记一条（不带目标 / 带目标）、没关联目标的提醒、详情页、设置页、密钥掩码、
`/__state` 与界面一致、没有 JS 异常。截图落在 `data/_ui/`。

`check-electron.mjs` 覆盖：窗口起来、preload 桥、自绘顶栏三个按钮、点卡片进详情、
**关窗只是收进托盘**（进程还在、窗口没销毁）。

**安全边界**：服务只绑 `127.0.0.1`，校验 `Host`（防 DNS rebinding）。
打包时用随机端口 + 每次启动的 token（首访 `?t=` 换成 HttpOnly cookie）。
开发时 token 为空是故意的——AI 要能直接打开。
