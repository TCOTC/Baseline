# 基线 / Baseline

> 和之前的你对比。

为每个目标定义**「什么算推进它」**，把活动归属到目标，累加成一条可以对比过去的曲线。

---

## 它解决什么问题

不是「不知道该做什么」。是**做了也不算数**——没有对比就没有位移，没有位移就没有进展。

所以它不做的事，和它做的事一样重要：

| 不做 | 为什么 |
|---|---|
| 不用红绿表示好坏 | 红色携带「错误 / 衰退」语义，会把它变成评判工具 |
| 不做进度条 / 百分比 | 方向性目标没有终点，百分比会暗示「快完成了」，那是假的 |
| 不做连胜 / 连击 | 把「中断」定义成失败，而中断是必然的 |
| 不画平滑曲线 | 数据是离散累积的，平滑会伪造出一个从未发生过的渐进过程 |
| 不替你判断该做什么 | 它只显示哪条线在动、哪条没动 |

## 快速开始

```powershell
cargo build
cargo run -- init      # 建库（幂等）。会把库的完整路径打出来
```

### 桌面窗口

```powershell
cargo run -p baseline-desktop
```

窗口不自己渲染界面：内核把整页渲染成一个 HTML 串，外壳把它挂在自定义协议上，
所以**没有本地服务、没有监听端口**。每次加载都现开库、现补快照、现渲染——
**F5 就是刷新数据**，不存在界面上数字比库里旧的情况。

`--db <路径>` 可以临时指向别的库，不写就用正式库。库的位置是
`%APPDATA%\Baseline\baseline.db`（可用环境变量 `BASELINE_DB` 覆盖），
和 CLI 共用同一个，不放在 exe 旁边——安装到 Program Files 后那个目录只读，
而库必须可写。

关于窗口本身的三件事：

- **顶栏是自绘的**，系统边框已关掉（`decorations(false)`）。顶栏横跨整个窗口宽度——
  它是窗口的边框，不是页面的头部，所以里面**不放产品名、不放日期**。
  缩放拖拽和 Aero Snap 都还在；唯一少掉的是 Win11 悬停最大化按钮时的 Snap Layouts
  弹层——tao 没有 `HTMAXBUTTON` 支持。
- **窗口按钮是照 Windows 量的，不是设计的**。尺寸（46×40）、图标（10px）、
  hover（`#d8d9da`）、关闭键 hover（`#e81123`）都来自在真实 Windows 11 标题栏上取样；
  图标直接用 **Segoe Fluent Icons** 的字符（`E921`/`E922`/`E923`/`E8BB`），
  也就是系统标题栏自己用的那四个字形，所以形状不可能不一样。细节见下面的「两个坑」。
- **左右两栏各自独立滚动**。一列是「三条曲线的现状」，一列是「这些天做过什么」，
  长度差得很远；绑在同一个滚动条上时，看时间线就一定会把卡片推出视野。
  右侧那条滚动条要**贴住窗口右边缘**，所以右内边距必须加在滚动容器自己身上
  （`.log`），**不能加在父级 `.right` 上**——加在父级会把 `.log` 整体推左一百多像素，
  滚动条跟着进来。这个坑踩过两次（第二次是重构时把内边距挪回父级），
  所以 `view.css` 里那段注释写明了原因。
- 界面上的 JS 异常会 POST 到 `/__jslog`，写进同目录的 `desktop.log`。
  窗口没有开发工具，异常不主动送出来就等于不存在。

### 记一条

时间是**下新上旧**的一条流水，最新的贴着底部输入框。写一句，回车——记的是「刚做了什么」。

输入框是一个**圆角框**，里面套一个无边框的多行输入区，「记下」按钮贴在框内右下角。
默认两行、随内容长高（到 160px 封顶）。**回车提交，Shift+回车换行**——
支持多行不该让「写完一句回车」变成要按两个键。

- **不选日期**。记录只能发生在现在。补记的语义由内核定：过去的日子冻结，
  **补一条旧账不会把曲线往回改，只会在今天抬一格**——意思是「你今天才记下来」，
  而不是「你三天前做过」。详见下面的「今天是个例外」。
- **写一句而不是点一下**。备注是这条流水上唯一有信息量的东西
  （「读完 CSAPP 第 3 章」和光秃秃一个计数不是一回事）。
- 提交后整页重来：Rust 重算今天的快照、流水重新落到底、输入框重新聚焦。
  不做局部插入——卡片上的数字和曲线末端一旦各算各的，迟早会显示成两个数。
- 有两个以上能手工打卡的目标时才出目标选择器；只有一个就把名字写进 placeholder。
- **选了目标之后，如果那个目标下有两条以上手工规则，才会再问一句「这条记录算哪条规则」。**
  只有一条就不问——那一条唯一能收它，内核自己会归。两条以上必须问，因为
  「它算哪一条」只有你知道，工具替你挑一条出来就是一条假曲线。
  没选就按「记下」，它不会提交，而是把选择器点亮：**该动手的地方自己说话**，
  而不是让你对着一句写在输入框里的提示猜（输入框里有字的时候那句提示根本看不见）。

  这条界线只划在「算不算数」上，不划在「记不记得下」上：一条记录永远记得下，
  无非是它归不到规则、于是不进任何曲线。

### 新建目标

左栏左下角有个加号。**没有数量上限**——这条线曾经由「最多 3 个」来守，
现在由别的东西守：建目标必须一并写下判定规则，写不出就不让建；而每张卡片底部
永远印着那条规则本身。数量的多少不是那条分界线。

### 目标详情

**点任意一张卡片**进入这个目标的详情页，整个窗口只显示它：

- 名字、当前值、为什么想做，以及一条**大两倍多的曲线**（卡片上 44px，这里 96px）。
  窗口既然只放一个目标，就没有理由还挤在卡片那个尺寸里。
- **判定规则**：列出这个目标的全部来源，可以删，也可以补一条。
- **修改 / 归档 / 删除**。
- 这个目标自己的记录。

详情页走的是**服务端路由**（`?goal=N`），不是 JS 切的视图——于是「只显示一个目标」
仍然由 Rust 一次渲染完成，JS 里不需要第二套模板。卡片在窗口里是个链接，
导出的单文件里不是（`file://` 上 `?goal=` 没有意义）。

**删除和归档不是一回事，界线画在「有没有记录」上：**

| | 条件 | 结果 |
|---|---|---|
| **删除** | **一条记录都没有** | 目标和规则一起没了。留给「建错了」。 |
| **归档** | 任何状态，**必须写一句原因** | 从列表消失，曲线和记录全留着，理由接在 why 后面 |

有记录时删除按钮置灰，并把理由写在旁边（「已经记了 23 条，所以删不掉……」）——
**别让人点完了才知道**。这条判定在 db 层也有一份，界面置灰只是提前说明，不是唯一防线。

归档要求写原因，和「一条记录都没动过才能删」是同一个出发点：**放弃也是事实，值得留一句。**
三个月后回看，`[归档 2026-10-06 22:34:05] 暂时不考了，先把项目做完` 比一个消失的目标有用。

### 建目标的对话

点开加号是**四步固定骨架**，不是自由聊天：

```
① 你想推进什么？        → 目标名
② 为什么是现在？        → why（为了推出③，不是问感受）
③ 什么算推进它？        → rationale，也就是卡片底部那句
④ 什么不算？            → 边界。最容易跳过、也最值钱的一问
⑤ 落到四种来源里的哪一种 → 当场算出当前值 → 建成
```

固定骨架解决的是设计文档 §11.1 那条「3 轮上限怎么定」：自由聊天只能靠 prompt
求它自觉，步数就是步数就不用调了；而且**「什么不算」这一问永远不会被跳过**。

拒绝也是机械的，不靠 AI 发挥：③ 空着不放行（「给不出什么算推进它，那不是目标，只是一句愿望」）；
来源需要对象时（git 仓库、外部数据）空着也不放行（「空着就等于什么都算」）；
④ 跳过了会记账但在确认页明说「没划边界，以后这条曲线会说谎」。

**AI 在这里没有位置。** 对话要问什么是产品定死的，判据（≥1 条来源、全部可计算、
当场算出当前值）也全是机械的。等真需要把一句话拆成几条来源时再说——那是另一件事。

（**唯一碰到 AI 的地方在别处**，见下面「AI 判定」：那不是在替你决定该做什么，
而是在你已经写好的几条规则里，判断「你刚才做的这件事」落在哪一条里。）

### 托盘

托盘图标左键 → 打开窗口**并把光标直接放进输入框**（省掉的那一步很小，
但正是这种小步骤决定了会不会真的去用）。悬停提示就是产品名。右键出菜单：打开 / 退出。

**关掉窗口不等于退出**，只是收进托盘——托盘是「随手记一条」的入口，关一次就退出的话
它就没意义了。真要退出走右键菜单。


### 自绘标题栏的两个坑

1. **`-webkit-font-smoothing: antialiased` 在 WebView2 上不起作用。** 图标边缘会泛蓝泛橙：
   实测真实系统图标的通道色差是 **6**（纯灰），开着次像素是 **130 以上**，摆一起一眼就看得出。
   真正管用的是把按钮提到独立合成层（`transform: translateZ(0)`）——透明背底的合成层
   不允许 LCD 文字。改完色差回到 6。
2. **图标不要自己画 SVG。** `shape-rendering: crispEdges` 会把 X 这类斜线切成台阶状，
   不用它又会糊。直接用系统字体，形状和 DPI 缩放都交给 Windows。

### 命令行

```powershell
# 1. 建目标。色板不写就自动挑一个没占用的
cargo run -- goal add "计算机基础" --why "基础知识匮乏，想打扎实" --color blue

# 2. 写清「什么算推进它」——这一步不做，曲线永远不会动
cargo run -- source add "计算机基础" --kind manual_checkin --rationale "读完一章，或做完一章题，算一次"

# 3. 打卡
cargo run -- checkin "计算机基础" --note "读完 CSAPP 第 3 章"

# 4. 补齐快照，然后看
cargo run -- tick
cargo run -- render --open
```

建完目标按 F5，窗口里就有了。

或者直接用演示数据跑一遍：`.\scripts\demo.ps1`（写 `data/_demo.db`，不碰你的正式库）。
想让窗口看演示数据：`cargo run -p baseline-desktop -- --db data/_demo.db`。

## 命令

| 命令 | 说明 |
|---|---|
| `init` | 初始化数据库（幂等） |
| `goal add <名> [--why] [--color]` | 建目标。色板自动分配未占用的 |
| `goal list [--all]` | 列出目标 |
| `goal show <名>` | 目标详情 + 判定规则 |
| `goal archive <名> --reason <原因>` | 归档。**必须写原因** |
| `source add <目标> --kind <类型> [--target] [--rationale]` | 加一条判定规则 |
| `source list <目标>` | 列出判定规则 |
| `checkin <目标> [--note] [--value] [--date] [--time] [--source]` | 记一条推进 |
| `tick` | 补齐每日快照（幂等，已写入的日期不改写） |
| `render [-o 路径] [--open] [--goal N] [--settings] [--window]` | 导出单文件 HTML（存档或临时看） |
| `status` | 终端速览各目标当前值 |
| `ai show` / `ai set` / `ai test` | 看 / 配 / 试 AI 判定 |

全局参数：`--db <路径>`，默认 `%APPDATA%\Baseline\baseline.db`。桌面窗口读的是同一个库。
`--window` / `--goal` / `--settings` 是**为了在浏览器里核对窗口里真实的排版**：
无头浏览器能按任意宽度截屏，比在真窗口上量快得多，也不抢焦点。

### 计分来源类型（四种，是上限）

| kind | 含义 | 状态 |
|---|---|---|
| `manual_checkin` | 手工打卡 | ✅ 已实现 |
| `git_commits` | 某个仓库的提交（可加「仅无 AI」） | ⏳ 规则可登记，未接线 |
| `external_metric` | 读外部数据（如 Learn-English 的复习记录） | ⏳ 同上 |
| `derived` | 由上面几个按公式组合 | ⏳ 同上 |

**不要再加第五种。** 规则复杂到需要文档解释那天，就是它变成「第 20 个仓库」那天。

## 三条设计纪律

### 1. 判定规则是产品的心脏

一个目标 = 一组计分来源。**没有计分来源的目标会被拒绝打卡**，因为它给不出「什么算推进它」。

示例——同一个 App 在两个目标下的归属完全不同：

| 目标 | 计分来源 | 效果 |
|---|---|---|
| 英语 | `Learn-English 的复习记录` | 在上面写 32 个提交，**英语曲线一动不动** |
| 不用 AI 也能做 | `标为无 AI 的仓库的提交` | 只有禁用 AI 的产出才计数 |

若按「项目 → 目标」简单累加，曲线会假装在涨。这正是要防的**假曲线**。

#### 规则决定数字，靠的是「归属」

规则写下来之后，还得有一条路让它真的算数，否则卡片底下印着的那句话就只是装饰。
这条路是**归属**：一条记录要算数，必须归到这个目标下的**某一条**规则上。

- 归属挂在 `checkin_goals.source_id` 上，也就是挂在「记录 × 目标」这个关系上，
  不在记录上。**一次做的事可以同时推进两个目标**，而两个目标下的规则是两句不同的话——
  记录只有一列的话，装不下「在英语那条规则下算、在计算机基础那条规则下不算」。
- **归属能唯一确定就自动归属**（那个目标下只有一条手工规则），有两条以上就由人指认。
  工具不替你猜：猜错就是一条假曲线。
- 归不到任何规则的记录**仍然记得下**，只是不进曲线。流水上会把它标出来
  （标签上写「·不计入」），详情页也会明说有多少条没归到规则。
- 删掉一条规则之后，原本归在它名下的记录会悬空。还在剩下唯一一条能收它的时候自动接手，
  剩两条以上就停在那里等指认——**数字会跟着掉，但界面上说得出为什么**。

一条记录和一个目标之间，只有这一处判断。判定口径（每条来源在截止某天的贡献）
只有一份实现：`metrics::source_value`。求值不再有「目标里有没有手工规则」那种整体闸门——
那种写法会让挂上来的任何记录都算数，规则就不再决定数字了。

#### AI 判定：不替你决定做什么，只判断「你做的那件事落在哪句话里」

左下角齿轮进设置页，配一个 OpenAI 兼容的接口（默认 DeepSeek）就能开。

它回答两个问题，而且是同一个问题：

- **这条记录算哪条规则？** —— 一个目标下有两条以上手工规则时，原本只能问你。
- **这条记录该归哪个目标？** —— 记一条的时候**一个目标都不选**，它去全部目标的规则里挑一条，
  连目标一起定下来。「记下来是第一步，归到哪个目标是第二步」——第二步以前只能人工做，
  于是不选目标记下来的记录就永远躺在流水里。

它的权力被四条规矩框死：

| 规矩 | 为什么 |
|---|---|
| **记录先落库，它只负责事后补判** | 一开始我把模型放在写库之前，界面就得等它——最长二十秒里什么都没发生，记录也没落库。**一条已经发生的事不该因为别人的服务器慢而记不下来。** 所以顺序反过来：写下来（这一刻就看得见），模型回来再把挂空的填上 |
| 只能从你写的候选里挑，或者回答「都不像」 | 返回候选之外的 id **一律作废**（`ai::parse_reply` 核对）。它不能新增规则、不能改写规则；挑不出目标就什么都不写 |
| **只填空着的格子** | 人挑过的目标、唯一能确定的那条规则，它碰都碰不到。它只在「说不好算哪条」「说不好算哪个目标」这种地方说话 |
| 置信度低于门槛（默认 80）就什么都不选 | 那条记录就留在「没归到规则」或「没关联目标」上，列表里数得出来，还给一个「让 AI 判这 N 条」的出口。**宁可留个待办，也不要一条假曲线** |

补判发生在记录落库之后，通常一两秒，界面上写着「AI 正在分类…」；整页重来时会把
你正在写的草稿放回去，不会因为后台刷新而丢字。

有一处它**没有**权限：一个目标下只有一条手工规则、而记录已经挂在那个目标上时，
那条规则是唯一确定的，它不会被问到——「唯一确定」的事不该花钱问模型。
但**没挂目标的记录哪怕全库只有一条规则也要问**：那时候要判的是「这件事算不算那条规则」，
而「都不算」只有它能回答。

它跑在**内核**里（`ai.rs`），不是在外壳里：CLI 和窗口走的是同一份判据和同一个顺序，
所以 `baseline checkin` 不写目标、不写 `--source` 也有同样的行为。命令行：
`baseline ai show` / `ai set` / `ai test`。补判失败的记录不会丢，列表上再点一次就行。

密钥加密后存在库里，口令编译在二进制里。**这不是安全边界，是提高门槛**——
能读库的人通常也能读 exe；它挡住的是按模式扫文件的窃取（到处翻 `sk-` 的那种）。
明文密钥只在内存里存在一趟，页面拿到的永远是掩码。

### 2. 快照写入后不再改写

曲线读的是 `snapshots` 表，不是实时回扫打卡记录。快照一旦落盘就冻结
（`INSERT OR IGNORE`）——以后改了判定规则，只影响**未来**的取值，已经落盘的那段曲线保持原样。

这是诚实性要求：不然「和之前的对比」可以随时被追溯篡改。

漏跑 `tick` 会留下空缺的日子，渲染时**沿用前一个已知值**——这对累积量是正确语义
（没记录 ≠ 归零），也正好就是阶梯线的形状。

#### 今天是个例外

**过去的日子冻结，今天每次重算。** 今天还没过完，用 `INSERT OR IGNORE` 把它钉死的话，
当天第一次渲染就把今天的值定下来了：之后每记一条，卡片上的数字会涨（那是实时累加的），
曲线却停在第一次渲染的位置——**数字和线的末端当场对不上，而且同一天记第二次就会撞上**。

这条规则顺带定义了补记：**补一条三天前的打卡，不会把曲线往回改，只会在今天抬一格。**

还有个配套要求：**数字和曲线必须同源**。`current` 和 `delta_week` 都取自快照序列，
不再单独实时累加。两边各算各的，迟早会显示成两个数——而用户只看得到「对不上」。

### 3. 零硬编码颜色

所有颜色走 CSS 变量。目标色通过给容器加一个类（`.blue` / `.green` / …）注入，
组件内部只写 `var(--c)`。新增一个目标只需分配一个色板，卡片、圆点、标签、曲线自动一致。

另外两条从踩坑里得到的约定：

- **SVG 内部类名必须加前缀**（`cv-line` / `cv-base` / `cv-dot`）。曾因 `.dot` 与时间线的
  `.dot` 撞车，CSS 把曲线末端的圆点拽出了坐标系，飞到半空。
- **数字必须 `font-variant-numeric: tabular-nums`**，否则同一列数字对不齐，没法扫读比较。

## 调试基础设施

窗口是「无系统边框 + 自绘顶栏 + 两栏各自滚动」，**很多东西读代码看不出来**：
拖动到底生不生效、最大化之后图标有没有跟着变、两栏是不是真的各滚各的、
窗口按钮画得跟系统像不像。这些只能真的动鼠标、再去量屏幕——所以它们进了仓库，
不是留在临时目录里的一次性脚本。

```powershell
# 端到端检查：真的点、真的拖、真的滚，再量屏幕确认。退出码 0/1
powershell -ExecutionPolicy Bypass -File scripts/ui-check.ps1

# 量一个真实 Windows 标题栏的按钮，验证 --cap-* 那组令牌还对不对
powershell -ExecutionPolicy Bypass -File scripts/measure-caption.ps1 -Process regedit
```

`ui-check.ps1` 覆盖 15 项：窗口按钮贴不贴右边缘、顶栏左半边是不是空的、
最大化/还原/最小化、顶栏能不能拖、拖动改不改尺寸、窗口在不在前台、
滚时间线时卡片动不动、滚卡片时时间线动不动、界面有没有 JS 异常。
截图落在 `data/_ui/`，可以对着看。

### 这里面埋着四个坑，都踩过

1. **`Process.MainWindowHandle` 不能用**，它按 Z 序取「第一个可见有标题的顶层窗口」。
   debug 构建带一个控制台窗口，应用窗口一最小化就掉到 Z 序底部，`MainWindowHandle`
   立刻指到控制台上——于是「点最小化后窗口变成 980×511 且再也点不动」这种**假 bug**
   就出现了，而且看起来非常像真 bug。按窗口类名（`Tauri Window`）找才对。
2. **坐标换算必须按窗口 DPI**，不能按「客户区宽 = 1280」反推——窗口一最大化就算错，
   表现为「第二次点最大化没反应」。
3. **滚轮只发给前台窗口。** 窗口不在前台时滚轮石沉大海，看起来就像独立滚动没实现。
   置前要用 `AttachThreadInput` 绕过前台锁定，而且**要把是否成功当结果返回**。
4. **`mouse_event` 的 WHEEL_DELTA 正负不能想当然。** 写反了的表现是「滚动没生效」，
   而时间线本来就在顶部——现象和真 bug 一模一样。

还有一条不属于测试台的：**所有 `.ps1` / `.psm1` 必须是 UTF-8 with BOM**。
Windows PowerShell 5.1 会把无 BOM 的脚本按 ANSI 读，中文注释直接变成语法错误。

## 技术选型说明

| 层 | 选择 | 为什么 |
|---|---|---|
| 语言 | Rust，单工作区 | 后续 git 适配器需要 |
| 存储 | rusqlite（bundled） | 现场编译 SQLite，不依赖系统 dll，打包不用附带 sqlite3.dll |
| 界面 | 静态 HTML + CSS 变量 + 手写 SVG | 设计规范逐字复用；不引图表库，曲线约 15 行 |
| 外壳 | Tauri 2（系统 WebView2） | 不捆绑 Chromium，产物几 MB |

**为什么界面是 Rust 渲染的字符串而不是前端框架**：整页只有三个数字、三条曲线、一列流水。
引入前端框架意味着设计规范要在 CSS 和 JS 里各维护一份，而「判定规则」这类核心逻辑
会在两端各长出一个版本。

**唯一的例外是那条流水**，它由 `assets/view.js` 渲染。原因只有一个：**虚拟滚动**——
它要知道滚到哪儿了、总共多高、该画哪几十行，而 Rust 那边出的是一整串静态 HTML，
这件事插不进去。所以 Rust 只出数据（一段 JSON）和固定行高，行的拼装在 JS 里。
**行的 class 仍然全部来自 view.css**，样式还是只有一份；搬过去的只是拼装。
行高为什么必须是固定值：虚拟滚动靠它算总高和偏移，行高一变滚动位置就会飘，
所以备注不换行、超长省略（悬停看全文）。

**为什么不起本地 HTTP 服务**：单机单窗口不需要监听端口。起了服务就要操心端口被占、
防火墙弹窗，以及「服务没起来所以窗口一片白」。自定义协议没有端口，生命周期跟着窗口走。

**为什么不是 GPUI**：它的官方 README 写着「学习 API 最好的方式是读 Zed 源码」，
且仍在 pre-1.0、API 常有 breaking change。而本项目绝大部分代码由 AI 辅助编写——
AI 对 GPUI 的训练数据极少且多是过时 API。这不是学习成本问题，是**核心生产方式被削弱**。
另外本项目要画 3 条 30 个点的曲线，GPU 加速不是瓶颈。
